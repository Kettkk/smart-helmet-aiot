# Fixed-video vision demo

This experiment verifies the smallest hardware-independent visual perception
loop:

```text
20-second hiking video -> sampled YOLO inference -> structured detections
                         -> annotated H.264 video -> latency/FPS summary
```

It demonstrates system integration and performance measurement. It is not an
accuracy evaluation because the fixed video has no ground-truth annotations.
Within the repository's research question, this experiment addresses only
latency, throughput, and sampled-frame detection continuity.

## Reproduce

Run the following commands; the runner downloads and SHA-256-verifies the
public-domain input automatically:

```bash
./scripts/run-vision-demo.sh
./scripts/run-vision-benchmark.sh
./scripts/plot-vision-results.sh
```

The first invocation builds the CPU-only image and downloads `yolo11n.pt` into
the persistent `vision-models` Docker volume. Later runs reuse both artifacts.

## Configuration

| Setting | Value |
| --- | --- |
| Input | `outdoor-hiking-20s.mp4` |
| Source | 1280×720, 30 fps, 600 frames, 20 seconds |
| Model | YOLO11n, COCO pretrained weights |
| Target class | `person` |
| Confidence threshold | 0.25 |
| Inference input size | 640 pixels |
| Frame strides | 1, 2, 5, and 10 |
| Effective sampling rates | 30, 15, 6, and 3 fps |
| Warm-up | 1 unmeasured inference |
| Device | CPU |

## Observed result

The following numbers were generated by the Docker workflow on 2026-09-20,
using an Apple M1 Pro host (10 CPU cores, 16 GB memory) and Docker Engine 27.5.1
for Linux/ARM64.

| Stride | Sampling rate | Mean latency | p95 latency | Pipeline rate | Continuity rate* |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 30 fps | 123.999 ms | 317.425 ms | 7.593 fps | 99.50% |
| 2 | 15 fps | 109.745 ms | 116.368 ms | 16.083 fps | 99.33% |
| 5 | 6 fps | 108.466 ms | 114.884 ms | 34.562 fps | 99.17% |
| 10 | 3 fps | 110.137 ms | 114.677 ms | 55.350 fps | 98.33% |

\*Continuity rate is the share of sampled frames containing at least one
`person` prediction. It is not precision, recall, or mAP.

These are machine- and configuration-specific observations, not general model
claims. The full run configuration is preserved in
`experiments/results/frame-sampling/benchmark.json`; the comparison table is
`summary.csv`, and every run retains its per-frame metrics and detections.

## Visualisations

### Frame-sampling trade-off

![Frame-sampling comparison](../experiments/plots/vision/frame-sampling-comparison.png)

Mean and p95 latency remain broadly stable for strides 2–10. The stride-1 run
shows heavier tail latency and is retained rather than discarded. Sampling
primarily reduces total work rather than making an individual inference faster.
Strides 5 and 10 process the 30 fps source faster than real time in this batch
pipeline; strides 1 and 2 do not.

### Per-frame latency

![Per-frame inference latency](../experiments/plots/vision/latency-over-time.png)

The stride-5 run is mostly stable near 108 ms, with a small number of visible
outliers. The distribution view makes this tail behaviour explicit.

![Inference latency distribution](../experiments/plots/vision/latency-distribution.png)

### Detection confidence

![Maximum person confidence over time](../experiments/plots/vision/confidence-over-time.png)

For the 119 stride-5 frames containing detections, maximum `person` confidence
ranged from 0.882 to 0.917, with a mean of 0.913. One sampled frame had no
detection. These are model confidence scores on one unlabelled clip, not
calibrated probabilities or evidence of accuracy.

## Interpretation

With a stride of five, the system requests six inferences per source-video
second. The observed CPU inference capacity was higher than that demand, and
the whole batch processed faster than the video's 30 fps source rate. Stride 5
is therefore the highest tested sampling frequency that crossed the real-time
source-rate threshold on this machine. This does not establish real-time
edge-device performance or detection accuracy in broader outdoor conditions.
